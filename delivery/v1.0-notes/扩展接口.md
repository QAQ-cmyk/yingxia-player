# 扩展接口与开发约定

应用使用 Kotlin 2.1.20、Compose、Media3 1.6.1、Room 2.7.1、DataStore 1.1.4；编译与目标 API 35，最低 API 26。版本锁定在构建脚本中，升级时应重跑播放器与权限回归。

## 模块边界

UI → `PlayerCommand` / `VideoRepository` → 业务规则 → Media3 / Room / MediaStore。除播放画面适配器外，界面不读取 ExoPlayer。原生 PlayerSurface 负责视频表面，自定义 Compose 层负责按钮和面板，SubtitleView 负责渲染字幕。

| 接口 | 实现及约定 |
|---|---|
| `MediaSource` | `sourceId`、`query()`、`resolve(video)`；首版 MediaStoreSource 读取媒体库，授权文件由仓库导入并持久化引用。后续来源实现同一协议，通过仓库接入；必须验证可访问性，不得直接绕过隐藏检查。 |
| `PlaybackController` | `state: StateFlow<PlaybackState>`、`events: Flow<PlayerEvent>`、`execute(command): Result<Unit>`；命令由主线程适配器执行，业务代码不操作 ExoPlayer。 |
| `VideoRepository` | `videos` 是排除隐藏和不可访问内容的普通查询；`hiddenVideos` 仅供显式隐藏管理。`requirePlayable` 重新检查隐藏与真实文件访问。收藏、历史、进度、书签与字幕引用持久化到 Room。 |
| `SubtitleProvider` | `load(contentUri)` 返回 `SubtitleAttachment`。首版限制 UTF-8 SRT/VTT、最大 5 MB，将字幕副本保存在应用私有目录，视频本体不复制。 |
| `PlayerFeature` | 稳定 `id`、`title`、`order`、`available(state)`、`onEvent(event)`；对应 UI 注册提供图标和 Compose 操作面板。 |

共享类型定义在 `core/Models.kt`：VideoId、VideoItem、PlaybackState、PlayerCommand、PlayerEvent、PlayerFailure。失败按访问权限、来源缺失、格式不支持、解码失败和字幕无效区分。输入命令失败通过 Result 与 Error 事件反馈，不应吞掉异常；协程取消必须向上传播。

## 添加一个功能

1. 在 `features` 实现 PlayerFeature，构造器接收 PlaybackController 等接口，不依赖具体引擎。
2. 在 `AppGraph` 的 FeatureRegistry 注册实例。ID 唯一；注册表按 order 排序并转发播放事件。
3. 在 `ui/FeaturePanels.kt` 的 UI 注册表加入同一 ID、图标和 Compose 面板。播放器工具列表自动根据注册表与 available 显示。
4. 通过 execute 发送命令，或监听状态/事件；Opened 和 Closed 时清理与单个视频关联的状态。
5. 如需新增命令，先扩展公共协议和适配器；普通面板扩展无需改播放器核心。动态下载和执行插件不在本版范围。

现有示例：LoopFeature 保存 A 点并发送 SetLoop；BookmarkFeature 通过仓库保存书签；SleepTimerFeature 使用单调时钟定时发送 Pause，优先于循环；SubtitleFeature 对应可切换轨道与本地字幕面板。

## 播放和手势不变量

- baseSpeed 持久化，effectiveSpeed 仅反映临时加速；临时速度不低于基础速度。暂停、手势取消、后台、切换视频、关闭播放器均恢复基础速度。
- 每个触摸序列只选择一个手势。横向拖动仅预览，UP 提交，CANCEL 丢弃；不会为了拖动自动开始播放。原生 SeekBar 保留键盘和无障碍调节能力。
- A-B 区间至少 500 ms，切换视频清空，跳到区间外清空。循环采用位置检查，实际误差受帧率、设备与解码器影响，不承诺逐帧剪辑精度。
- Activity 重建不重建播放引擎；非配置变化的 onStop 暂停。Media3 管理音频焦点及耳机拔出事件。不会在后台持续播放。
- 短暂音频焦点丢失也会清除临时加速并暂停，焦点恢复后由用户手动继续。

## 媒体、权限与数据

媒体标识使用卷名 + MediaStore 行 ID；授权文件使用规范化媒体标识（可获得时）或 URI 的 SHA-256。同一媒体可规范化时复用记录；不同第三方内容提供方若给同一文件不同 URI 且无媒体映射，系统无法保证跨提供方去重。

Android 8–12 请求 READ_EXTERNAL_STORAGE；13 请求 READ_MEDIA_VIDEO；14 及以上同时声明/请求 READ_MEDIA_VISUAL_USER_SELECTED。回到应用重新扫描授权范围，部分授权提供重新选择入口。拒绝后仍可通过 ACTION_OPEN_DOCUMENT 选择本地文件，尝试保留读取授权。没有 MANAGE_EXTERNAL_STORAGE、写入相册或联网权限。

扫描与缩略图在后台执行，Compose 网格按需加载封面。扫描结果在 Room 事务中合并最新用户记录，避免覆盖扫描期间的新收藏/隐藏/进度。不删除失效媒体的关联记录；来源重新可用时可恢复。数据库版本 1，后续变更必须添加 Room Migration，不使用破坏性重建。

批量收藏和隐藏以每批最多 900 个 ID 执行，并共享一个 Room 事务，兼容旧版 Android 的 SQLite 参数数量限制。新增批量操作应遵循相同限制。

隐藏会保留原文件、收藏、书签和进度。所有新页面必须使用普通 videos/bookmarks 查询；所有新播放入口必须调用 requirePlayable。隐藏管理不能被当作普通队列来源。没有密码保护或加密承诺。

官方依据：[Android 部分媒体访问](https://developer.android.com/about/versions/14/changes/partial-photo-video-access)、[Media3 Compose](https://developer.android.com/media/media3/ui/compose)。
