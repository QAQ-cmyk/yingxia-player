# 映匣 1.2.1 测试记录

> 以下记录的是 1.2.1 发布时的检查。之后的版本已移除 B 站网页、账号入口和网络权限；这里提到的在线路径不再属于当前应用。历史细节见 `delivery/v1.*-notes/`。

日期：2026-11-12。versionName 1.2.1 / versionCode 4，最低 API 26，目标 API 35。

## 修复与依据

用户报告点击「账号」后，登录页出现前就返回视频。旧入口是不带返回地址的通用 passport 登录页；官方手机登录组件会先检查已有会话，然后按 gourl、来源页或默认首页返回，因此可能根本不显示表单。1.2.1 为入口明确设置官方账号中心返回地址，停止当前页面加载后进入该登录流程。未登录显示官网表单，已有会话及登录成功返回账号中心。页面归属改为校验 passport/account 域名，避免视频查询参数误选账号标签。

先增加设备回归，再运行旧实现，检查因返回地址为 null 失败（red-regression.log）。修复后保留同一断言并通过。该受控测试模拟官网重定向规则，不是假称登录了真实账号。

开发阶段试过直接打开账号中心，再由官网转登录；真实页面会先加载整页再转，增加等待。最终入口改为直接打开带 gourl 的登录地址。另修复正式包小屏检查发现的说明文字与密码入口重叠：手机登录页的说明从绝对定位恢复为正常文档流，保留全部文字和官网表单。不读取字段、不代勾选或代填账号。最终重新构建和运行全部检查，没有强制禁止离开账号页，也没有清除原有 Cookie 或修改本地数据库。

## 官网与安装手动检查

- 最终 Debug 包点击账号后，实际到达 `https://passport.bilibili.com/h5-app/passport/login?gourl=https%3A%2F%2Faccount.bilibili.com%2Faccount%2Fhome`，显示手机号/验证码和账号密码登录入口；随后多次读取仍停留在登录页，播放器/广告控件数为 0。见 live-final.log。
- 同签名正式包覆盖升级后，在 Android 14 模拟器打开账号登录页面，并通过可见按钮切换到账号密码登录；说明文字不再覆盖切换按钮。截图位于 screenshots-v1.2.1/，页面文字记录在 release-login.log。实际输入账号、密码或短信码没有执行。
- 覆盖升级演练没有预先填入个人收藏或书签，不能据此声称人工验证了所有历史记录；本次没有数据库结构或数据迁移变更。

## 范围与限制

没有真机验证，没有使用真实账号登录；验证码、真实已登录账号中心内容、登录状态跨重启和不同厂商 WebView 仍未验收。已有会话与登录成功后的返回由受控回归覆盖，不能替代真实认证流程。

本轮只在 Android 14 模拟器重跑。Android 8/13/16、公开视频实播等早期结果请查历史版本记录，不算本轮重测。三轮完整回归被 Windows 模拟器宿主退出中断：qemu-system-x86_64-headless.exe 异常码 0xc0000005，证据见 android-14-host-interrupted*.log 和 emulator-host-crash.log；随后将模拟器图形模式从 swiftshader_indirect 改为 lavapipe 后重新执行最终检查，应用 APK 没有改动。该模式见 [Android 模拟器官方说明](https://developer.android.com/studio/run/emulator-acceleration)。短时检查通过不证明长时间运行稳定，历史宿主退出问题仍保留在 v1.2-notes/测试记录.md。
