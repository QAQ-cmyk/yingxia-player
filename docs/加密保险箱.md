# 加密保险箱（1.6.1）

## 使用

1. 打开「我的 → 加密保险箱」，设置并确认至少 8 个字符的独立密码。
2. 选择「加密本地视频」，或在普通视频卡片菜单选择「移入加密保险箱」。长按多选后也有「加密」入口。
3. 确认应用提示，保持应用在前台。程序先加密、校验副本，再复核原件内容，最后请求系统移除原件。Android 版本和文件来源不同，可能还会出现系统授权窗口。
4. 没有批准系统移除时，相册原件仍然可见。保险箱会保留已校验的加密副本，显示待完成状态；可点击「继续移除相册原件」。
5. 在保险箱中点击「播放」，操作与普通播放器一致：八档倍速、长按临时加速、滑动/进度条定位、双击暂停、全屏、亮度音量、锁定、双指缩放、裁黑边、上一条/下一条、三种播放顺序、A-B 循环、定时暂停、收藏和时间书签。续播、收藏、裁黑边和书签另存为本机加密记录；显示名称写入加密元数据。返回列表或锁定前保存当前进度，重新解锁后续播。
6. 「恢复到相册」会校验解密输出，保存到 `Movies/映匣恢复/`，并保留加密副本。确认不再需要后，可通过删除按钮永久删除保险箱副本。

旋转与全屏切换保留同一播放器及播放状态。切到后台或退出保险箱会立即锁定、释放播放器并关闭解密通道。正在进行的加密/恢复会中断；未校验完成不会请求移除原件。系统移除窗口若触发后台锁定，返回后需重新解锁核对结果。

完全本地：应用没有 `INTERNET` 或 `ACCESS_NETWORK_STATE` 权限，没有云同步、服务器、遥测或账号；系统云备份和设备迁移均被关闭。保险箱不是云盘。共享的倍速/外观设置仅为本机偏好，不含视频身份或私密备注。

## 必须了解的边界

- 密码不上传、不保存明文，没有重置或找回服务。忘记密码不能恢复视频。
- 卸载应用、清空应用数据会删除保险箱。Android 自动备份/设备迁移及应用的 JSON 记录备份均不包含它。第一版没有独立加密备份导出，请在卸载/换机前恢复到相册。
- 这是真实加密，与原来的「隐藏」不同。隐藏仅过滤列表；加密后只有确认相册原件移除，才能说该原件已不在相册。
- 云相册已上传的内容、回收站、其他文件副本、第三方相册缓存以及以前导出的记录备份，需要用户另行管理。删除本机媒体行不是云端删除或存储介质安全擦除承诺。
- 完成移入后，普通资料库的该视频记录与书签被清除，不保留其普通收藏/续播。保险箱名称不进入搜索、历史或新的 JSON 备份。
- 页面使用 `FLAG_SECURE` 防截图与录屏；不承诺对抗 root、被篡改的系统、已控制进程的攻击者或拍摄屏幕。
- 操作需要容纳额外副本的可用空间。磁盘满、权限变化、损坏、取消或中断时，不会以“已完成加密移动”报成功。请勿在有唯一重要资料的设备上跳过备份。

## 实现与扩展

目录：`app/src/main/java/cn/yingxia/player/vault/`。本机注册在 `AppGraph.vault`，独立于普通 `VideoRepository` 播放入口和图片加载器。

| 类型 | 职责 |
| --- | --- |
| `VaultCrypto` | 版本化密码封装、密钥生成、原子写入及 SHA-256 完整校验 |
| `VaultSession` | 仅在内存持有已解锁原语；加密/认证元数据，打开可定位的分段解密通道；锁定关闭全部通道 |
| `VaultStore` | 私有文件目录、加密/校验/恢复、加密状态日志与恢复中断清理 |
| `VaultCoordinator` | 前台串行操作、系统授权结果、待完成导入、后台锁定、普通资料库记录清理 |
| `VaultVideoRepository` | 私密队列和加密播放记录，实现 `VideoRepository`，不使用普通 Room、导出或缩略图缓存 |
| `VaultPlaybackSession` | 私密 Media3Controller、工具和协程的生命周期；旋转保留，锁定前释放并刷盘 |
| `PlayerUiSession` | 共享播放界面的会话参数，普通与私密仓库独立；面板不访问全局普通资料库 |
| `VaultDataSource` | Media3 数据适配，仅通过已解锁会话读取认证片段，不生成明文视频缓存 |
| `VaultHost` | 密码、选择/确认、列表、进度、恢复及安全播放界面 |

### 文件格式 v1

全部存放在 `Context.noBackupFilesDir/encrypted-vault/`，FileProvider 不暴露此目录。

- `keyset.bin`：ASCII 头 `YINGXIA-VAULT-1`、16 字节随机盐、12 字节随机 nonce、AES-256-GCM 密文。明文负载是两个长度前缀的 Tink keyset；仅在内存序列化。封装密钥采用 PBKDF2-HMAC-SHA256、600,000 次迭代、256 位。AAD 绑定格式头和盐。
- `<UUID>.vault`：Google Tink `AES256_GCM_HKDF_1MB` Streaming AEAD 视频。AAD 为 `yingxia-vault-v1:video:<UUID>`，可随机定位并逐段认证。
- `<UUID>.meta`：AES-256-GCM 加密的 UTF-8 JSON，包含原名称、源标识、摘要、时长、移除/恢复状态。AAD 为 `yingxia-vault-v1:metadata:<UUID>`。
- `<UUID>.playback`（1.6.1 新增）：AES-256-GCM 加密 JSON，保存版本、视频标识、进度、收藏、裁黑边及最多 256 个书签。AAD 为 `yingxia-vault-v1:metadata:playback-v1:<UUID>`，与原元数据分离；不能互换视频记录。单条记录损坏时保留原密文并拒绝覆盖，不影响其他视频。1.6.0 无此文件时按默认值打开，不迁移或重加密原视频；修改名称仍写入 `.meta`。
- `.part` 和 `.tmp` 在加密阶段也只有密文。文件落盘同步后原子重命名，元数据提交后才允许请求移除原件。不会因为扫描或解密失败而自动删除密文。

恢复在 Android 10+ 使用 `MediaStore.IS_PENDING`，校验完成后公开；Android 8/9 先在恢复目录下带 `.nomedia` 的 `.pending` 子目录写入，校验后移到正式文件名并通知媒体扫描。仅清理本次创建的未公开输出，不删除已公开恢复文件。恢复中断状态保存在加密元数据中。

系统移除动作有单独的持久标记。如果进程在系统确认后退出，下次解锁在拥有完整媒体读取权限时核对媒体行，完成普通记录清理；部分授权不能把“查询不到”当作已删除。受限权限下应先重新授权，然后解锁核对。若原件已被其他程序修改，摘要不匹配会阻止继续移除。

保险箱与普通播放器共用 `PlayerPage`、手势和 `yingxiaTools()`；每个工具使用传入的 `PlayerUiSession.repository`，不可从全局 AppGraph 取得普通仓库。锁定会取消私密定时器及事件订阅、释放播放器、同步保存最后一条小型加密记录、清空内存列表，然后销毁解锁会话。队列封面使用锁图标，不调用图片加载器。

新增保险箱工具必须检查解锁会话，只把私密信息写入认证加密元数据；不能复用普通缩略图磁盘缓存、普通历史、日志或 JSON 备份。调整密码算法、段大小、AAD 或磁盘格式时需提供新版本格式和迁移，禁止直接覆盖既有密钥文件。密钥封装/文件删除相关修改应补充破坏性场景测试。
